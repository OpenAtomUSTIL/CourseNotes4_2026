## **包管理器**
首先什么叫包管理器`package manager`呢， 是电脑系统自动安装，配置，删除和升级软件包的工具。
**人话:电脑版无可视化界面版的软件商店**。这个工具可以一定程度上免除小白对于安装配置软件环境上的烦恼。
### **常见包管理器**
#### a.macos `homebrew` 
Homebrew 是 **macOS 上广泛使用的第三方包管理器**，便于在`Mac`相关生态上进行生态管理。也能用在`Linux`和 `WSL(适用于Windows电脑的Linux子系统)`上

macOS 不安装完整 Xcode 也可以配置基础 C/C++ 开发环境。执行 `xcode-select --install` 可以安装 Xcode Command Line Tools，其中包含 Apple Clang、Git 等常用开发工具。
##### **`homebrew`下载步骤**
由于`Mac`系统属于`Unix`系统所以系统内文件管理相较于`Win`来说要好理解很多。macOS/Linux 与 Windows 在文件系统组织方式上存在明显区别，并不使用 `C:`、`D:` 这样的盘符作为主要组织方式。
直接`cmd+空格`输入`terminal` 回车然后 在当中输入下面的命令即可安装
```shell
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# 下一步 会提示homebrew加入到PATH 加入之后就可以开始安装软件了
eval "$(/opt/homebrew/bin/brew shellenv)" 
```
如果你想要下载什么软件就可以直接使用
`brew install +软件名`
比如你想安装新版本的`gcc`或者`clang`
```shell 
brew install gcc 
brew install clang 
# `llvm` 包提供 LLVM/Clang 相关的一套编译工具链，例如 Clang 编译器及其他 LLVM 工具。
brew install llvm #这个是一个编译器整合包 包含编译 调试器和链接构建工具等等，可能会比较慢。
```

#### **b.Windows `scoop`**
##### 官方下载方式 
这个是专用于Windows的命令行软件包管理器。灵感参考来自`homebrew`。因此使用的方法大体类似，但是这里要注意一个很严重的问题。
==***！！！！！不要装到`C盘` ***== 

因为如果不做环境变量配置改动`scoop`会默认装在`c`盘。众所周知，两大Windows开发者后悔的事情，一个是中文用户名，另一个则是糟糕的环境配置。
为了避免出现很难搞的问题，我们需要先做如下配置
```powershell
# 切记WIN+R 打开powershell 一行一行粘贴下面的命令即可，#后面是注释。
$env:SCOOP = 'D:\Scoop'
[Environment]::SetEnvironmentVariable('SCOOP', 'D:\Scoop', 'User')

# 配置全局下载 如果你执行的是-g之类的全局下载命令会下载到这个位置上
$env:SCOOP_GLOBAL = 'D:\Scoop\ScoopGlobal'
[Environment]::SetEnvironmentVariable('SCOOP_GLOBAL', 'D:\Scoop\ScoopGlobal', 'Machine')

# 允许执行本地/已签名脚本（只做一次）
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser -Force

# 安装
irm get.scoop.sh | iex
```
这样如果网络没有问题就会开始下载了，进度条跑完基本上就没有问题了。

或者直接运行一个安装脚本这样只需要执行一个长命令即可完成
```powershell
irm get.scoop.sh -OutFile 'install.ps1'
.\install.ps1 -ScoopDir 'D:\Scoop' -ScoopGlobalDir 'D:\Scoop\ScoopGlobal' -NoProxy
```

如果要安装某个软件就使用 `scoop install 软件名`
删除就使用`scoop uninstall 软件名`即可。还有很多其他的命令欢迎同学们自行学习了解。

##### 网络问题的国内镜像解决方 案

如果无法正常访问 GitHub，可以使用国内同步的 Scoop 镜像完成安装。

> 注意：以下属于第三方镜像方案，并非 Scoop 官方源。网络条件允许时，优先使用官方安装方式。

首先打开普通 PowerShell，不需要管理员权限：
```
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```
下载国内镜像提供的安装脚本：
```
Invoke-RestMethod https://gitee.com/scoop-installer-mirrors/Install/releases/download/archive/install.ps1 -OutFile install.ps1
```
然后安装到 D 盘：
```
.\install.ps1 -ScoopDir "D:\Scoop"
```
安装完成后，将 Scoop 本身的仓库切换到 Gitee 镜像：
```
scoop config scoop_repo https://gitee.com/scoop-installer-mirrors/Scoop
```
然后可以添加常用的 `main` bucket：

```
scoop bucket add main https://gitee.com/scoop-installer-mirrors/Main
```

如果需要 `extras`：

```
scoop bucket add extras https://gitee.com/scoop-installer-mirrors/Extras
```

最后测试：

```
scoop update
scoop search git
```

如果能够正常搜索软件，说明 Scoop 基本配置成功。

---

需要特别注意：

```
Scoop 镜像
    │
    ├── Scoop 本体             ← 可以镜像
    │
    ├── main / extras 等 Bucket ← 可以镜像
    │
    └── 软件真正的安装包        ← 不一定镜像
```

Scoop 的 Bucket 本质上主要保存软件安装信息，例如：

```
git.json
python.json
nodejs.json
```

里面会记录软件真正的下载地址。
因此即使 Scoop 和 Bucket 使用国内镜像：

```
scoop install xxx
```

某个软件本身仍然可能需要从 GitHub Releases 或软件官方网站下载。
所以“换 Scoop 镜像”主要解决的是：

```
Scoop 本体下载
+
Bucket 获取/更新
```
它不能保证所有软件安装包都能够完全脱离国外服务器下载。
所以还是建议搞一个魔法。

## **编程范式**
在讲这个之前，需要先给各位简单科普一些高级语言的语法，首先讲一下什么是 结构体。
### 结构体 `struct`
我们都知道C语言中存在数据类型这种语法，作用自然是用来描述数据对应的类别。比如是整数 小数还是字符。
```c 
int a = 10;
long l = 100;
long long ll = 100000;

float f = 3.14;
double d = 3.1415926789;
long double ld;

char c  = 'a'; // char c = 65
```

但是仅凭这些类型远不足以对现实生活中的事物进行抽象，因此语言的设计者们也考虑到了这一点，提供了一种自定义数据类型的方式，这种方式就叫做结构体
语法如下 
```c 
struct  TypeName {
	属性的类型  属性名; 
};
```
举个例子 比如说，你希望做一个学生管理系统，那就需要一个学生的类型来描述学生的状态和相关信息 ，那我们可以怎么写呢。
```c 
struct Student {
	char *name;// 学生姓名
	int age;// 学生年龄
	char *gender; // 学生性别
};
```
这样一个学生的类型就创建好了如果你想定义一个学生`zhangsan`那可以怎么写呢。
```c
struct Student zhangsan;
```
那如果想要访问zhangsan的属性应该怎么访问呢，用`.`
```c 
zhangsan.name = "zhangsan";
zhangsan.age = 20;
zhangsan.gender = "male";
```
这样张三的属性就初始化好了。

### 面向对象和面向过程 
什么叫面向过程呢，之前也有提及就是在面对一个事物的时候，直接的描述整个事物发展的流程。
比如说你想吃饭，那用面向过程的内容应该怎么描述呢
```c  
#include <stdio.h>
char *zhangsan = "zhangsan";// 人 名字
void Eat(char* name){
	printf("%s在吃烧烤！\n",name);// 吃这个行为
}
void Drink(char *name){
	printf("%s 同时也喝了啤酒\n",name);// 喝这个行为
}
int main(){
	Eat(zhangsan);
	Drink(zhangsan);// 也就是张三吃了烧烤也喝了啤酒。
}
```
也就是有一个行为叫吃 ，有一个行为叫喝。定义了这两件事情之后，我们选择一个谁吃，也就是主体是我们需要讲清楚的事情。

但是面向对象就不一样了。
```c 
#include <stdio.h>

typedef struct Person Person;
struct Person {
	char *name;
	void (*Eat)(Person *);
	void (*Drink)(Person *);
};
void EatBBQ(Person *person) {
	printf("%s正在吃烧烤\n", person->name);
}
void DrinkBeer(Person *person) {
	printf("%s也正在喝啤酒\n", person->name);
}
int main() {
	Person zhangsan;
	zhangsan.name = "zhangsan";
	zhangsan.Eat = EatBBQ;
	zhangsan.Drink = DrinkBeer;
	
	zhangsan.Drink(&zhangsan);
	zhangsan.Eat(&zhangsan);
	return 0;
}
```
从面向对象的角度上来说，吃烧烤和喝啤酒这两件事情是属于张三这个人的，也就是说，重点在于，**张三**吃的烧烤喝的啤酒。行为本身是依托于人这个主体的。
从这个例子来说，面向过程整体更关注的是整个程序的步骤，也就是完成一个任务需要做什么工作；而面向对象关注的是程序中会涉及到什么对象，程序可以围绕着对象做完什么事。
